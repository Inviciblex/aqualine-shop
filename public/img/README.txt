Фото товаров (самохостинг).

Файлы вида <id>-<n>.webp — фото товара с id, по порядку в галерее.
Их отдаёт nginx с того же origin (/img/...), внешний прокси не нужен.

ВАЖНО: сами .webp лежат в git (надёжная копия), но НЕ в Docker-образе
(public/img/*.webp в .dockerignore). nginx отдаёт их из bind-mount тома (см.
docker-compose*.yml: ./public/img → /usr/share/nginx/html/img). Так образ не
пухнет с ростом каталога, а фото обновляются без пересборки.

Как пополнять локально:
  1) npm run fetch:images -- --push
     — скачает фото из колонки images таблицы в этот каталог (WebP),
       пропустит мёртвые ссылки и проставит пути /img/<id>-<n>.webp в таблицу
       (без --push — только скачает и напечатает пути для ручной вставки).
  2) закоммитьте новые файлы public/img/*.webp в git.

ВНИМАНИЕ: после простановки в таблице путей /img/... исходные ссылки поставщика
пропадают — заново скачать фото из таблицы уже нельзя. Копия в git (и на сервере)
становится единственной. Не удаляйте их из git, пока не перенесёте на отдельное
хранилище.

На сервере: каталог public/img/ рядом с docker-compose.prod.yml (приезжает с
git-чекаутом либо заливается по SFTP).

В колонке images таблицы несколько фото разделяются вертикальной чертой «|».
