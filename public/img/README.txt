Фото товаров (самохостинг).

Файлы вида <id>-<n>.webp — фото товара с id, по порядку в галерее.
Их отдаёт nginx с того же origin (/img/...), внешний прокси не нужен.

ВАЖНО: сами .webp НЕ в репозитории (public/img/*.webp в .gitignore) и НЕ в
Docker-образе. nginx отдаёт их из bind-mount тома (см. docker-compose*.yml:
./public/img → /usr/share/nginx/html/img). Так образ не пухнет с ростом
каталога, а фото обновляются без пересборки.

Как пополнять локально:
  1) npm run fetch:images -- --push
     — скачает фото из колонки images таблицы в этот каталог (WebP),
       пропустит мёртвые ссылки и проставит пути /img/<id>-<n>.webp в таблицу
       (без --push — только скачает и напечатает пути для ручной вставки).

На сервере (боевой compose): создайте каталог public/img/ рядом с
docker-compose.prod.yml и загрузите в него .webp по SFTP.

В колонке images таблицы несколько фото разделяются вертикальной чертой «|».
